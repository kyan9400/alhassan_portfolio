3:T5a3,Proofbench is an open-source evaluation platform I built with Claude Code for an LLM agent that can do damage: a customer-support agent for a small shop that refunds money, cancels orders and reads other people's data. Almost every question worth asking about it has an exact answer, so it is decided from an effect log rather than by asking a model: what moved, by how much, on which order, whether something forbidden was attempted even if the shop refused it, and whether another customer appeared in the reply.

The agent is qwen3.5:9b running locally on one GPU. On the baseline it was fully correct on 75.0% of attempts and did nothing dangerous on 95.8%. The dominant failure is an agent that reasons correctly and then never calls the tool. Run with more randomness, the pass rate stayed exactly the same while the safety rate fell to 83.3%: it paid out on two of five planted instructions, which is why the two rates are kept apart.

Reply quality is the one thing a model judges, and the judge is measured: against five blind model raters it agreed at kappa 0.93 (95% CI 0.78–1.0). Recorded runs replay through the graders in 4 s instead of 18 minutes of GPU, and a CI gate fails if any grader's counts move, after a test showed the first version passing with a critical grader switched off. Every number on the live dashboard is re-graded by the current code, and the README keeps the measurements that turned out wrong, with why.4:T614,Switchyard is an open-source gateway I built with Claude Code for a few GPUs serving many users. An inference server can run only a few requests at once and queues the rest out of sight, where nothing can reorder or refuse them; a plain load balancer spreads that overload evenly and hides it everywhere. Switchyard keeps the queue in front of the servers, sends each replica only as many requests as it has slots, and refuses what cannot be served in time with a retry time. It is written in Go with no dependencies outside the standard library.

Measured on one RTX A4000 serving qwen3.5:9b through two replicas, Ollama and llama.cpp on the same weights, against a plain round-robin proxy fed identical open-loop chat traffic: at 1.0 requests a second the proxy got 6 of 212 requests a first token within 10 seconds and 150 failed; Switchyard got 78, failed none, and refused the rest in at most 3 ms. With a replica killed under load the proxy returned 15 errors to clients and Switchyard none, finishing 7 of the affected requests on the live replica. Routing conversations back to their cache made no measurable difference at this scale, and the write-up says so.

The first benchmark run found three bugs in the gateway, all of them making it look worse, and getting the second GPU replica running found a Docker and NVIDIA interaction that silently moved another service's model onto the CPU; both are fixed and written up. A live dashboard and the real-GPU results page are public, and every table is recomputed from the raw logs in the repository.5:T5ae,Ledgerline is an open-source payments platform I built with Claude Code to show what a bank's core needs: money that is never created, lost or moved twice, even when everything around it fails. A double-entry ledger in Kotlin and Spring Boot keeps an append-only event log in PostgreSQL; balances are projections rebuilt from it, every write is idempotent, and an audit recomputes the books. Card payments, refunds and payouts run as state machines and sagas on top of it, and every change reaches Kafka through a transactional outbox.

It is proven by breaking it while a client keeps paying: services, PostgreSQL and Kafka killed, networks cut, answers cut off mid-way. Over 11 chaos scenarios and 40,461 requests (4,188 of them sent twice at once), a checker found nothing lost and nothing done twice. Load tests found the hot spots: the ledger does about 430 transfers a second on one CPU, shedding the excess instead of falling over.

A LightGBM model on real-time features from Kafka caught 88% of fraud at 0.7% false declines against 37% for tuned rules, measured against a simulator's hidden truth; ClickHouse analytics agree with the ledger to the kopeck. Merchants get a gRPC API, signed webhooks and a TypeScript SDK: with the service killed mid-payment, all 1,085 changes still reached the example shop.
