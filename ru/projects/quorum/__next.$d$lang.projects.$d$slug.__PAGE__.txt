3:T4f9,Quorum is a replicated key-value store I built with Claude Code to learn distributed consensus by implementing it: Raft written from scratch in Go with nothing outside the standard library, an exactly-once client protocol, and a write-ahead log on disk. The point of the project is the evidence that it is correct, not the store itself.

A deterministic simulator ran 2,000 seeds of a five-node cluster through 78,099 crashes and 77,959 partitions; all 1,587,823 client operations were linearizable. Three Jepsen-style runs on Linux, five real processes with fsync on and a fault every five seconds, put 151,083 operations through 111 partitions, isolated leaders and kill -9s, every history linearizable, and every node came back from disk at the same commit index. Three nodes on a shared four-core VM sustain about 2,300 writes and 7,500 linearizable reads a second at 64 clients.

The tests were tested too: five bugs known to break Raft were planted one at a time. Random simulation caught three and missed two that need an exact sequence of events, so those got scripted tests; the first Jepsen harness missed a stale-read bug until half its clients were pinned to single nodes. The live demo is public and has checked over half a million operations since it went up.4:T64f,Elektroservis keeps its engineering (PTO) documentation in a network archive of about 4.1k PDF, DOCX, XLSX and RTF files, about 1.5k of them with text. From April to October 2026, under civil-law contracts, I built a search service over it: an engineer types a cable mark, a document code, an equipment designation or a phrase and gets the document, the PDF page (or Excel sheet and rows, Word section), a text fragment and the network path. Documents never leave the company network.

Search is hybrid, with no LLM generation: a custom inverted index over words and designations, plus FAISS semantic search on sentence-transformers embeddings (all-MiniLM-L6-v2). Designations are matched by general rules: look-alike Latin and Cyrillic letters, spaces and hyphens do not break a match, while numbers and marks are never substituted. Scans are detected automatically and selected pages go through Tesseract + Poppler OCR. The backend is FastAPI, the interface is plain HTML/JS, and it runs as a systemd service on Ubuntu Server with an atomic index swap and rollback.

Code and mark queries went from 9–10 s to 1.2–1.7 s and phrase queries from 55–70 s to 2–4 s; after the move to the inverted index, p95 is 0.18 s on 55 control queries. Quality is held by 739 pytest tests and a 104-query control set with top-1/top-5 metrics. I built it with AI agents (Codex, Cursor, Claude Code): I gathered the requirements, wrote the agent briefs, reviewed the changes and checked them on the production index. The client accepted the work in September 2026. The code is private, so the diagram shows the architecture.5:T614,Switchyard is an open-source gateway I built with Claude Code for a few GPUs serving many users. An inference server can run only a few requests at once and queues the rest out of sight, where nothing can reorder or refuse them; a plain load balancer spreads that overload evenly and hides it everywhere. Switchyard keeps the queue in front of the servers, sends each replica only as many requests as it has slots, and refuses what cannot be served in time with a retry time. It is written in Go with no dependencies outside the standard library.

Measured on one RTX A4000 serving qwen3.5:9b through two replicas, Ollama and llama.cpp on the same weights, against a plain round-robin proxy fed identical open-loop chat traffic: at 1.0 requests a second the proxy got 6 of 212 requests a first token within 10 seconds and 150 failed; Switchyard got 78, failed none, and refused the rest in at most 3 ms. With a replica killed under load the proxy returned 15 errors to clients and Switchyard none, finishing 7 of the affected requests on the live replica. Routing conversations back to their cache made no measurable difference at this scale, and the write-up says so.

The first benchmark run found three bugs in the gateway, all of them making it look worse, and getting the second GPU replica running found a Docker and NVIDIA interaction that silently moved another service's model onto the CPU; both are fixed and written up.
